The Nameplate Style row's Look panel becomes the pattern for every Style page. Names get a full page of their own, with rows per kind of unit. Nameplates and names get themes, and the main themes pick one of each.

Summary

What changes

One template

Every way to style a part lives in a Look panel like the Nameplate Style row's: a live sample, tabs, pick by picture, Reset on each setting. Each setting now also says where its value comes from: this row, the Default row, the theme or the game.

Name Style, scaled up

Names get rows like Nameplate Style's: All names, then Your target, Group members, Friendly players, Enemy players, Service NPCs and the rest. Each row has its own Look with six tabs: Text, Color, Edge, Backdrop, Second line and Extras.

Plate and name themes

There are 19 plate themes and 21 name themes. Each main theme gets its own matching pair, made from its colors and art, and a few stand alone (Clean, Raider, Storybook, Subtitle…). Plate themes cover only the bar; names come from name themes. The three old name presets become name themes.

Main themes use them

Picking Gilded Codex on General brings Gilded Codex names, and plates follow General as they do today. A plate or name theme picked on its own page stays when the main theme changes. A new column on General's Pages tab lets a theme leave whole parts alone.

I read the code on main at commit 00381a4. The mock-ups use the addon's real data: the 16 themes from StyleThemes.lua, the bar textures, bar shapes and target marks from Textures/, the preview lake, and the eight bundled fonts. The game's own font and art are stand-ins, as in Tools/style-lab. Nothing in the addon has changed. The only repo change is two Name Style and Nameplate Style frames added to style-lab, so the "before" pages could be drawn.

While you were away

Decisions I made, each easy to reverse

You said to approve suggestions, so I picked a default wherever there was a fork. Each one is listed here so you can overrule it.

D1
"This page" means the Nameplate Style row's Look panel (the tabbed panel with the sample plate, from today's commits 3419f26 and 80bc293). It's the newest and most complete styling UI in the addon, so it's the template.
If you meant the whole Nameplate Style page (rows grid plus panel), the plan still fits: Name Style and Cast Bar Style copy that page's shape too.
D2
Plate and name themes are a live layer under your settings, not settings written over them. A row's setting falls back to the Default row, then the part's theme, then the game. Switching themes never wipes a row's own changes. The two picks, plateTheme and nameTheme, stay out of the main theme's ThemeKeys(), so a main theme never writes them. They're only saved with its Undo snapshot.
Changed in round 3. In round 2 these keys joined the theme's written settings. That would have reset a plate theme you picked by hand on every main theme pick (StyleThemes.lua 975-980), which broke D3.
D3
A plate or name theme picked by hand sticks. Changing the main theme leaves it alone. "Follow main theme" is always the first card, to go back.
D4
Name themes made from a main theme use its Small names font. That's Friz for most themes and the theme's own font for Slate, Obsidian and Carbon, the same rule the themes use for unit frame names (StyleThemes.lua: "the themes' thin fonts go faint there"). The fancy fonts go to the themes that stand alone (Storybook uses Almendra).
D5
Reaction colors keep their meaning, tuned to the palette. Hostile stays red, neutral yellow, friendly green, each pulled a little toward the theme's colors (Gilded Codex's hostile is a warmer red). The tuning rule is in the theme library section.
D6
The Name Style Preset menu is removed. Its three presets become name themes with the same values: Like the game's names (now "The game's"), Bold and Subtle. Anyone on one of them lands on the same look.
D7
The look of service NPC titles moves to Name Style's Second line tab: brackets, icons in place of titles, and icon size. Which kinds of service NPCs show stays on the Nameplates page, with a link to the new tab. The keys don't change, so nobody loses a setting.
D8
The build order is Names first, then plate themes, then main themes, then the other pages. Every step ships on its own.
D9
Anything that depends on reading a unit's name, health or level is marked "needs a test". These values can be secret on retail in fights and on Forever, and the addon already works around that in PlateParts.lua and the Heal Vision plan. Each such feature has a fallback.
D10
Name Style's All names row sets names everywhere. Plate themes hold only bar settings: texture, border, shape and background. So the name on a full plate goes row, Default row, Name Style's All names, the game. Set a font once and it shows on name-only plates and on full plates. Change it on one plate row only when that row needs to stand out.
Round 1 found two unrelated fonts for one name. Round 2's fix still let a plate theme sit above All names. Round 3 takes text out of plate themes altogether.
D11
"Follow General" is today's plate look. Plates already take General's texture and border, and the theme's veil (PlateHealthStyle.lua). The first plate theme card follows General's live values, so a texture you set on General by hand still reaches plates. Pick a named plate theme and it takes General's place for plates only.
D12
A real "inherit" value, and a one-time move to it. Today's plateName* settings always hold a value, so a theme could never show through them. They get an "inherit" value, and a one-time migration turns values still at their defaults into it. Values someone changed stay theirs. Profiles whose main theme is "The game's" also get nameTheme = "game", so nobody's names change on update without a theme behind it.

Open questions, with my default

  • Should the template reach every Style page, or stop at the nameplate pages for now? Default: every page, one release at a time (see Other pages).
  • Should the main theme cards on General show a nameplate and a name, as in the mock-up? Default: yes. It's the clearest way to show that a theme reaches plates now.
  • Is a colored name outline worth its cost? It draws each name eight extra times. Default: offer it, and measure with 40 names on screen before shipping.
The template

What the Look panel already does, and what it gains

This is today's Nameplate Style row Look panel, redrawn with the four additions. Click the tabs, point at tiles (the sample shows them before you pick), and hold "Hold to compare".

The live panel is under Nameplate Style. This spot shows where each part sits.

Already there (kept as is)

  1. The title shows where you are (Nameplates > Nameplate Style >), with Pop out, Dock and X.
  2. A live sample with Hostile, Neutral, Friendly and Player picks, the lake or plain dark, and Closer.
  3. Pointing at a choice shows it on the sample with "Preview: not saved".
  4. One tab per group, with a gold dot on any tab holding a change.
  5. Each setting has a gold name, its value, and a Reset that shows only once it's changed.
  6. Pick by picture: tiles for textures, fonts and borders; buttons for small choices; color chips; sliders. After 12 tiles, a More tile.
  7. A footer saying what's changed, with Reset all.

Added

  1. Where it comes from. A tag on each setting: This row, Default row's, Plate theme: Gilded Codex or The game's. It replaces today's mix of "Usual", "Default row's" and "Use General" with one idea. The first tile in each grid, Inherit, says what it gives and from where.
  2. Hold to compare. Hold the button and the sample drops this row's own changes, so you can see before and after.
  3. Copy look / Paste. Move a look from one row to another (Target to Focus) without redoing it by hand.
  4. Start from a theme. Load a theme's look into just this row, then change it from there.
How it fits

Where a setting's value comes from

Every setting resolves the same way on every page. The first layer that has a value wins.

  • Nameplate Style uses the same four steps for the bar. Its step 3 is General's live texture, border and shape while the plate theme is "Follow General" (D11), so nothing changes for plates on update.
  • The name on a full plate skips step 3: Default row, then Name Style's All names, then the game (D10).
  • Values a main theme wrote (cast colors, General's texture) are this row's own, but their tag says Set by theme: Gilded Codex while they still match what the theme wrote. StyleThemeEdited already makes that comparison.
  • This is how PlateRowLook.lua already resolves a row, with step 3 and a real "inherit" value added (D12).

The rows

One row per ns.NAME_GROUPS entry whose names plates draw (Effects.lua 23-108): Hostile, Neutral, Friendly and Service NPCs, Friendly players, Group members, Enemy players, the three Minions groups and Target. "Service NPCs" means the same units on both pages. My name and Critters stay the game's own names over heads, which addons can't style. Guild names are the Second line tab.

Rows only show settings that make sense for them: service icons on All names and Service NPCs, class colors on player rows. "Your target" sits second so it wins over the rest, as on Nameplate Style. Per-kind keys come from a NameRowDefault, built like Core's MarkRowDefault, so profiles and sharing carry them.

All names keeps today's plateName* keys, with a real "inherit" value and a one-time move to it (D12).

Themes

The plate and name theme library

Every main theme brings a plate theme and a name theme made from its own data: the bar texture, line color and thickness, bar shape and veil for plates (bar only: no text); the Small names font, palette-tuned reaction colors and a second-line color from its ornament for names. Some themes add a glow (Fel Pact, Void Whisper, Moonlit Glade, Emberforge) or a dark band (Slate, Obsidian, Carbon). Then the themes that stand alone.

How a family theme is made

Plate textureThe theme's styleTexture
Plate borderThe theme's line and lineSize
Bar shapeThe theme's styleBarShape
Bar colorThe game's, darkened by the theme's plate veil where it has one (as now)

HostileRed, 35% of the way to the theme's stop color
NeutralYellow, 35% of the way to its cast color
FriendlyGreen, 45% of the way to its health color
Second lineGrey, 60% of the way to its ornament

Build plan
Six releases, each one whole

	

		
1 · Template upgrades
    
			
  • StylePages.lua rows.Look: a source tag on each Heading, an inherited first tile, Hold to compare, Copy and Paste, and Start from a theme.
    • 
			
  • A panel.source(key) hook giving { value, from }, so each page tells the panel its chain.
    • 
			
  • Nameplate Style's panel switches over first: PlateRowUsual becomes its source hook.
    • 
			
  • The Text tab's chain reads Name Style's All names (D10). Today PlateRowUsual reports plateNameOutline as the usual outline while NameLook keeps the game's: that existing mismatch gets fixed here.
    • 
			
  • Style-lab draws the panel open (the frames added on this branch).

		
2 · Name Style rows
    
			
  • New NameRowLook.lua, built like PlateRowLook.lua: the rows, keys and resolution. PlateParts.lua and PlateGuild.lua read through it.
    • 
			
  • Rewrite CreateNameStylePanel: theme strip, scene, rows grid, Distance and timing.
    • 
			
  • The six tabs. The new drawing (glow, backdrop, outline color) goes in a small NameDress helper. Its textures are made once per pooled plate and hidden when unused.
    • 
			
  • NameRowDefault (like MarkRowDefault) and RecordKey on the page, so profiles and modules carry the rows.
    • 
			
  • The "inherit" value and the one-time move (D12).
    • 
			
  • A ROMAN guard on plate names' plain SetFont fallback and on NameLook. Today only the preview has one; the rest relies on CreateFontFamily.
    • 
			
  • Service title settings get a link on the Nameplates page (D7).

		
3 · Plate and name themes
    
			
  • New PlateThemes.lua and NameThemes.lua, made from THEMES at load time (the rules above), plus the themes that stand alone.
    • 
			
  • Keys plateTheme and nameTheme, both "main" by default, kept out of ThemeKeys() (D2).
    • 
			
  • Step 3 of the chain in PlateRowLookFor and the name resolver. For plates, "main" reads General's live values, as PlateHealthStyle does today (D11).
    • 
			
  • The theme strips on both pages.

		
4 · Main themes
    
			
  • THEMES entries name their plates and names (their own key by default).
    • 
			
  • The cards on General draw a plate and a name.
    • 
			
  • The reaches switches, as a column on the Pages tab (GeneralStyle.lua's PAGES): styleThemeReach<part>, all on by default. ApplyStyleTheme skips keys of a part that's off, and StyleThemeEdited ignores them.
    • 
			
  • Tools/offline/check.lua: every plate and name theme key is real, and Undo still works with a plate theme picked by hand.

		
5 · Cast Bar Style
    
			
  • Its tabs become rows. Its existing keys become each row's own, and each row keeps its "These bars" pick (own, Default's or the game's).
    • 
			
  • No theme layer: Casts() keeps writing the Default row. The template's Set by theme tag shows where.

		
6 · The rest
    
			
  • One page per release, in the order in the table above.
    • 
			
  • Each gets a style-lab frame of its Look panel and a What's new entry.

Revisions
What I changed after looking at each round

	
I drew each round, screenshotted it, read it back as a player would, and fixed what didn't make sense. An independent review was the last round.

	

		
Round 1
First full draft: plan, four mock-ups, theme library. Reading the screenshots back I found:
			
  • Name and plate samples in the theme cards overlapped.
  • The inherited tile read "Theme'sGilded Codex".
  • Numbered callouts broke their text into a column of single words.
  • Far names were unreadable.
  • A design gap: the name on a full plate (Nameplate Style's Text tab) and on a name-only plate (Name Style) had no link, so one name could get two fonts.

		
Round 2
Fixed the layout bugs.
			
  • Theme cards stack the name over the plate.
  • The inherited tile is called Inherit and says what it gives.
  • The callouts sit beside the panel, not inside it.
  • The Cast Bar mock-up got its rows.
  • The page fits a phone.
  • Added D10, Name Style feeding plate names.

		
Round 3
An independent review checked every claim against the code. What changed because of it:
			
    
				
  • The theme picks stay out of the main theme's written keys (D2). Before, a main theme pick would have reset a hand-picked plate or name theme.
    • 
				
  • Plate themes hold only bar settings, so All names really reaches full plates (D10).
    • 
				
  • "Follow General" keeps today's plate look and anything set on General by hand (D11).
    • 
				
  • A real "inherit" value with a safe one-time move (D12). Before, the theme could never show through the existing name settings.
    • 
				
  • Cast bars keep the colors the theme writes, now tagged Set by theme. Their rows start as they do today: Nameplates on the Default row, the rest on the game's.
    • 
				
  • Profile and module claims corrected to how Profiles.lua and ProfileModules.lua really work.
    • 
				
  • Name tabs renamed to match the shared Look groups (Glow, Background, Level). Rows now match ns.NAME_GROUPS, with three Minions rows.
    • 
				
  • Per-row plate size and name place are now "needs a test". New risk rows for ROMAN, pooled textures and migration.
    • 
				
  • The reaches switches moved into the Pages tab.
    • 
				
  • One reset button per scope. Settings that are switched off say "Off" instead of "The game's".
    • 
				
  • The sticky nav is gone, and some samples were redrawn so they read.
