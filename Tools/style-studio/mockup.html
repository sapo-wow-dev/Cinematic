Tools

Undo / Redo

One history per session, Ctrl+Z / Ctrl+Y and the title bar arrows. Each step is named ("Target · Name font → Friz Quadrata"). Resets, looks and theme picks are steps too. It replaces db.styleThemeKept, which is written on every pick and read only by a test.

Reset, one meaning

Reset means back to what the value follows: the variant above, then the theme, then the game's. Scopes are one menu: setting, part, variant, frame, everything. The menu shows how many settings each scope touches, and an Undo toast follows. This replaces eight reset buttons with five different meanings.

Find a setting

Searches every property by name, recipe, part, frame and synonym (thickness → Border size, see-through → Opacity). Enter jumps there and flashes the row. The same index answers /cine find.

Changed

A rail view of everything you set, grouped by frame, each with ↺. It does for Style what "In this rule" does for CQL. A gold dot on each frame in the rail marks a look that differs from the theme.

Compare, Peek, Test

Hold Compare to see the frame as it was when you opened the Studio. Hold Peek to fade the Studio and Settings so you can see the real frames. Test plays the frame's motion (casts, numbers, letterbox, cards) and honors its timing settings.

Why isn't it showing?

When the frame can't be seen live, a status line under the stage says why: "Off: Enable Style › Nameplates [Turn on]", "Dominos draws your action bars", "Needs Chat › Behind bubbles [Open]". This covers every silent no-op the audit found.

Copy look / Paste

Works per recipe, so a tooltip's Text can go to Names. Paste shows only when there is somewhere it can go. Today it shows on single-look pages where it can't paste anywhere.

Looks

Every frame has a strip of looks: the theme's, the game's, built-in looks and your saved ones, shareable as CINEL1:. It replaces Preset dropdowns, Layout's destructive Preset and the never-wired "Start from a theme".

Every page, what it becomes

Saved settings keep their keys. The hub, its icons, tabs and switches stay where they are, so the layout is still the switch tree. Each page id opens the editor on its frame and variant. Rows marked moves change where a control lives and need your OK (Decision 2).

One build, one test run

Build & tests

Build order (inside one build)

  1. Style/Studio/: Editor (frames, variants, parts, recipes, where each value comes from), History, Find, Controls, Recipes, the Window host, the Page host, and Stages.
  2. Frame specs for all 29 frames. These are data, not hand-built pages. Every property names its existing db key.
  3. Each Style page calls ns.StyleEditor(page, "compact"). Remove the old builders: PresetMenu, Sub, themeLook, VisionRows on Style pages, and the hand-made widgets in Combat Text, Text on You, Plate Layout and Tint.
  4. The fixes on the list above, each with its audit card.

Tests

  • Offline stylestudio.lua checks that:
    • every spec key is in DEFAULTS and is read at runtime;
    • every frame fits 300 px and 480 px on both clients;
    • no raw kit widget is left on a Style page;
    • Reset counts are right and Undo restores every value;
    • Find reaches every property;
    • the switch-tree sweep gives 0 warnings.
  • Style Lab: studio-* frames for every theme, as cql-*.
  • Audit kit: a card and an old/new matrix for each changed behavior: the Card Types switch, the Visions reset scope, the hidden Name settings, the four value adapters, the greying fixes and Minimap's border color.
  • In game, one run: the TestKit test stylestudio on Forever, then retail. It walks every frame, every hotspot and every Looks tile, then Reset → Undo, then Find. One shot per frame, and no deverror or BLOCKED lines.

Risks

  • Size. This is the biggest UI change the addon has had: about 7–9k lines touched and about 4k removed. Two things contain it: the keys don't move, and both hosts share one editor.
  • Taint. The Studio is our own frame and never parents a secure frame. Docking reuses the CQL editor's dock, so there's no more SettingsPanel sliding.
  • Speed. Stages redraw only when something changes, at most once a frame. Rail dots come from History's changed-index, not from scanning db.
  • Secrets. Stages use the preview-match copies and never read live secret values.
